# Контроль визитов NUPPI

## Что уже реализовано

- привычный сценарий медика в Telegram не изменён;
- каждая серия фотографий после выбора роддома и ввода врача хранится как один визит;
- для фотографии отдельно сохраняются проверки товара, материала, повтора, обработки, задания и геолокации;
- автоматическая логика выдаёт только «Принято» или «На проверке» и никогда сама не обвиняет медика;
- «Отклонено» может поставить только руководитель на сайте и только с причиной;
- на сайте есть счётчики итогов, фильтр по итогу и сводка по медикам и визитам;
- в управлении сайтом можно назначать задания по медику, городу, роддому, врачу и периоду;
- выбранный итог учитывается при обычной выгрузке Excel.

## Что требуется для точной проверки всех продуктов

1. Эталонные фотографии каждой упаковки и материала: NUPPI F1/F2/F3, GOLD 1/GOLD 3,
   плакаты, стенды, буклеты и другие POS-материалы.
2. Для каждого эталона — точное название, допустимые варианты дизайна и признаки правильного размещения.
3. Список пилотной группы из 5–10 медиков и тестовые задания примерно на 100 визитов.
4. Проверка руководителем спорных результатов пилота, чтобы настроить пороги без ложных обвинений.

## Геолокация

Telegram не передаёт координаты обычной фотографии автоматически. Для настоящей GPS-проверки
нужно добавить медику кнопку «Отправить геолокацию» и получить его согласие. Также нужны
координаты роддомов и допустимый радиус, например 200 метров. Пока интерфейс медиков не меняется,
поэтому геолокация хранится как «Не запрашивалась» и не влияет на принятие фотографии.

## Локальный сайт и облачный бот

Надёжный вариант — одна центральная PostgreSQL-база и отдельное объектное хранилище для фотографий.
Облачный бот и локальный сайт подключаются к одной базе по защищённому адресу; копировать SQLite-файл
во время работы бота небезопасно и на больших объёмах медленно. Для перехода нужны:

- строка подключения к управляемой PostgreSQL-базе;
- S3-совместимое хранилище и ключи доступа для фотографий;
- закрытый VPN или список разрешённых IP для локального сайта;
- окно переноса данных и резервная копия текущего диска Render.

До переноса текущая облачная SQLite-база остаётся единственным источником истины.
